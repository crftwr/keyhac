# Why this directory looks empty

Both of this skill's references are **copied in at bundle time** rather than
checked in here, and `tools/build_skill_bundle.py` is where that is wired:

| In the bundle | Copied from |
|---|---|
| `references/configuration.md` | `doc/configuration.md` |
| `references/config-api.md` | `doc/config-api.md` (generated by `make api-reference`) |

`config-api.md` goes into the action-authoring bundle as well. Two installed
skills cannot share a file - each is uploaded on its own - so a reference both
need is carried twice, which is cheaper than the alternative: telling a model to
fetch a URL, which is what the action skill used to do and which failed in
measurement.

Neither is restated in `SKILL.md`, and that is the point. `doc/configuration.md`
is already the authoritative description of key expressions, table conditions,
remapping and one-shot modifiers - maintained, read by users, and corrected when
it is wrong. A paraphrase of it living in a skill would be a second copy to
drift, and a confidently wrong rule costs more than a missing one: that is
exactly how `keyhac-action-authoring/references/quirks.md` came to ship a false
statement about identifiers (issue #58).

So `SKILL.md` carries only what neither reference does - the loop, the rules for
editing somebody's live `config.py`, and what can and cannot be checked without
pressing a key.

This file is excluded from the bundle: it is addressed to whoever is working on
Keyhac, not to the model.
